# Initialization implementation coverage

This document records engineering verification and reporting coverage, not a completed downstream ranking. The main centered grid contains 76 families; the separate warm-start and dense NF4 grids contain five and eight treatments/controls respectively, each with an additional accepted anchor. ## Formula and runtime boundary

The common task runtime retains column normalization, full denominator gradients, ambient norm arithmetic, dense projection, implicit adapter scale one, and FP32 factors/magnitude. MiniLM retrieval and Qwen extraction use frozen BF16 base weights; Aircraft uses frozen FP32 base weights with BF16 autocast. Both factors train at fixed rank. Centered nonzero recipes use `W + (BA - B0A0)` with identical autocast for the two products. This preserves the starting function, while differing from literal low-precision storage of a paper's residual base. Warm starts and quantized bases have separate registries and initial-quality diagnostics. Public `dora.py` is not changed by these initializer backends.

Fourteen data/weight-aware recipe implementations are documented with pinned primary sources in [initialization_literature.md](initialization_literature.md). The independent formula audit covers 21 determinate cases, including source LoRA-GA/LoRA-One gamma defaults, EVA whitening derived from activation singular values, CorDA damping retry, FILet projected diagonals, full-population LoRA-DA scaling, all three CNT formulas, and source-shaped IniLoRA Adam/StepLR updates across the 5,000-step boundary. Dense CPU FP32 decompositions are explicit solver adaptations. CPU thread count, Torch version, source, matrix/calibration contents, and relevant recipe arguments bind caches.

Exact full EVA rank redistribution, full TLoRA rank/scale allocation and frozen-down training, full MiCA frozen-up training, LoRA-SB middle-matrix training, and LoRA-Pro optimizer modifications are not implemented by this fixed-rank train-both initializer study. The later source review of Gap-Init, GME-Init, and LoRA-Null is recorded separately in [initialization_extension_review.md](initialization_extension_review.md); these methods are absent from the frozen main grid. Initializer derivatives must not be reported as tests of these full methods.

## Verified optimizations and corrections

- IniLoRA caches its source prefit before final gain/balance scaling, retaining the source U/P draw layout and 20,000-step setting. GPU prefit disables TF32 locally and restores the parent task's flag. Cache keys include device and precision. A measured Qwen 2048×2048 layer prefit took 4.039 seconds; its balance variant reused the fit in 0.01936 seconds. This is one-layer preprocessing evidence, not a full-model speed result.
- CNT caches the exact target average before rank selection and factor gain/balance. Its key binds W, ordered raw Grams, mode, damping, pseudoinverse tolerance, source, Torch version and CPU threads. Tests forbid pseudoinverse calls on cache hits, check bitwise uncached parity, validate all three modes, preserve seed invariance and factor scaling, and reject corrupt/mismatched entries. Actual Qwen layer cold/hit timings were cross 3.893/0.203–0.216 seconds, self 10.224/0.210–0.218 seconds, and shift 9.102/0.203–0.205 seconds, with 16 calibration Grams and eight CPU threads.
- NF4 thresholds use the exact FP32 values of bitsandbytes CUDA literals. Four random matrix shapes including 2048×2048 and 128 threshold/adjacent adversarial values were bitwise equal to the isolated bitsandbytes 0.49.2 reference. Quantization remains dense dequantization; no compressed serving memory or throughput claim follows.
- Warm-start and quantized diagnostics identify modules through stable accepted-runtime class membership and initializer metadata. Fresh backend objects now find previously injected modules. The ten dedicated tests cover this boundary, checkpoint replay, accepted RNG consumption, BF16 geometry, gradient flow, and preservation of the caller's original weight Parameter.
- Calibration files are verified once per unchanged filesystem signature and memory-mapped on factor-cache misses. Weight-only recipes do not read irrelevant calibration tensors. This matters for the Qwen per-batch Gram archive, which is approximately 25 GB.

The 686-configuration registry engineering audit exercised all registered settings at ranks two and eight with rectangular BF16 weights, preserving 602 centered initial forwards bitwise. Its source hashes predate the final TF32/CNT-cache and diagnostic-filter corrections; retain that evidence as versioned coverage. Final-source tests and the independent formula delta audit validate those bounded changes. They are not silently relabeled as a rerun of all 686 configurations.
